# 13: 識別子衝突判定の精密化（バックログ・v1 必須ではない）

## 目的

`shape.NameVisibleAt` による識別子衝突判定を、現在の保守的な近似から、より精密な判定へ移行する。DEC-11.22 で「方針のみ確定・実装は別イテレーション」と明記された、v1 スコープ外の任意タスク。

## 対象 DEC・FR

- DEC-11.22（識別子衝突チェックの判定精度の将来方針。**現状は方針記録のみ**）

## 現状の保守的近似（何を精密化するか）

`internal/shape/typesutil.go` の `NameVisibleAt` は意図的に安全側の近似になっている:

- (a) 同一ブロック内であれば、対象の使用箇所がローカル変数の宣言より**前**にあり技術的には安全な場合でも、「同名のローカル変数が同じブロックに存在する」というだけで衝突と判定する（宣言前後の位置関係を区別しない）。
- (b) universe scope（`len`・`cap` 等の組み込み識別子）との衝突は判定対象外。

将来的にはこの 2 点を精密化する（宣言前後の位置関係を区別する判定、universe scope との衝突チェック）。

## 変更ファイル

- `internal/shape/typesutil.go`（`NameVisibleAt` の拡張）
- `internal/fix/` テスト・`testdata/fix/<case>`（精密化を検証するケース）

## 実装メモ

- 宣言前後の位置関係は、`types.Object.Pos()` と使用箇所 `pos` の前後比較で判定できる（同一ブロック内でのみ意味を持つ）。
- universe scope の衝突は、現在 `Parent() == nil` で打ち切っている探索を、`types.Universe.Lookup(name)` のチェックに置き換え/追加する形で扱える。
- 精密化により「壊れたコードを生成する」リスクが増えないよう、golden test で両方向（fix 可になるケース／新たに衝突扱いになるケース）を必ず検証する。
