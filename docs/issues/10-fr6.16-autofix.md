# 10: FR-6.16 の auto-fix（重複 import 統合・削除）

## 目的

単一ファイル内で同一 import path が複数回・異なる alias で import されているケース（FR-6.16、03 で検出済み）の auto-fix を提供する。canonical な alias/path に統合し、重複した import 文を削除し、ファイル内の参照を canonical 側へ書き換える。

## 対象 DEC・FR

- FR-7.16（重複 import を canonical に統合、重複 import 文を削除、qualified identifier を canonical へ書き換え。自明な変換に該当する場合のみ）
- DEC-11.20（import 文の削除を伴うため astutil を使う）
- FR-7.5（自明な変換のみ）

## 変更ファイル

- `internal/fix/fix.go`（重複 import 統合の分岐。決定ロジックで定まった canonical alias に寄せ、`astutil.DeleteNamedImport` で余剰 import 文を削除、参照を書き換え）
- `testdata/fix/<case>/{input,golden}/`（新規ケース）
- `docs/fix-cases.md`（対応ケースを追記）

## 実装メモ

- canonical の決定は 4 節の決定ロジック（多数決 or config）に従う。統合後の alias に衝突があれば自明変換に該当せずスキップ（診断のみ）。
- 参照書き換えは `shape.SelectorIdentsOf` で対象 import の全 PkgName を集め、canonical へ寄せる。
- 統合後のコードが実際にコンパイル可能な有効 Go コードになることを golden で担保する。

## 終了条件

- [ ] 重複 import 統合の入力/golden を追加し golden test green。
- [ ] 統合後のファイルがコンパイル可能な有効 Go コードであること（golden がそれを表現し、テストで型チェックが通る）。
- [ ] 衝突で自明変換不可のケースはスキップ（無変更）することを確認。
- [ ] 対応ケースが `docs/fix-cases.md` に記載。
- [ ] `go test ./...` 全 green。
