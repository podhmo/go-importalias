# 02: FR-6.11（同一 alias → 複数 path）検出の結線

## 目的

同一パッケージ内で 1 つの alias 名が複数の異なる import path に対応している不整合（FR-6.11）を検出し、go vet analyzer から診断できるようにする。型（`shape.AliasCollision`）は既にあるが、`decide.Decide` が算出しておらず analyzer も報告していないため、この軸を結線する。

## 対象 DEC・FR

- FR-6.11（同一 alias に複数 path が対応 → 不整合として検出）
- DEC-11.12（FR-6.10 の `Decision` とは別型・別スライス `[]AliasCollision` で返す。無 alias は対象外）
- DEC-11.16（`AliasCollision.Occurrences []Occurrence` で診断位置を持つ。各 path につき代表 1 件）

## 変更ファイル

- `internal/decide/decide.go`（`byAlias` 集計を追加。`Decide` の返り値を `([]shape.Decision, []shape.AliasCollision)` に変更。`o.Alias == ""` は集計対象外。出力は決定的にソート）
- `analyzer.go`（collisions をループし `c.Occurrences[0].Pos` に `pass.Reportf`。ゼロ値防御）
- `internal/fix/pipeline_test.go` ほか `decide.Decide` の既存呼び出し元を新シグネチャに追従

## 実装メモ

- `docs/draft.md` の `internal/decide/decide.go` スケッチに `byAlias`（`map[aliasKey]map[string]shape.Occurrence`、path ごとに最初の 1 件を代表）実装例がある。これを踏襲する。
- `len(byPathOcc) <= 1` の alias は衝突ではないのでスキップ。
- 診断メッセージ例: `alias %q is used for multiple import paths in this package`。
- **auto-fix はこの issue のスコープ外**（検出のみ）。fix は 09 で扱う。

## 終了条件

- [ ] `internal/decide` の単体テストで、同一 alias → 複数 path の入力に対し期待どおりの `[]AliasCollision`（Package/Alias/Occurrences）が返る。
- [ ] `testdata/src/` に FR-6.11 の新パッケージ（例: 同じ alias `x` で 2 つの異なる path を import）＋ `// want` を追加し、`analysistest` が green。
- [ ] FR-6.10（同一 path → 複数 alias）の既存検出が壊れていない（既存 `TestAnalyzer` green）。
- [ ] `go test ./...` 全 green（シグネチャ変更に伴う呼び出し元の追従込み）。
