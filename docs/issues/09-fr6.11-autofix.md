# 09: FR-6.11 の auto-fix（import path 自体の追加・削除）

## 目的

同一 alias が複数の異なる import path に対応しているケース（FR-6.11、02 で検出済み）の auto-fix を提供する。衝突側の import を別 alias に振り替える必要があり、import 宣言の追加・削除を伴うため `astutil` を使う。

## 対象 DEC・FR

- FR-7.8 → DEC-3.1（OQ-5 解消。v1 で auto-fix を提供。ヒューリスティックは testdata＋`docs/fix-cases.md` で都度確定）
- DEC-11.20（同一 import path 内の別名変更は direct mutation、**import path 自体の追加・削除を伴うケース（FR-6.11）にのみ astutil を使う**）
- DEC-11.6（`astutil.AddNamedImport`/`DeleteNamedImport`、書き戻しは `go/format.Node`）
- FR-7.5（自明な変換＝衝突なし・セマンティクス不変のみ）

## 変更ファイル

- `internal/fix/fix.go`（FR-6.11 解決の分岐を追加。`astutil` で衝突側 import を別 alias へ振り替え、qualified identifier も書き換え。書き換え後の alias が衝突するなら FR-7.5 に該当せずスキップ）
- `testdata/fix/<case>/{input,golden}/`（新規ケース）
- `docs/fix-cases.md`（対応ケースを追記。11 で作成した土台に追記）

## 実装メモ

- 「衝突した側の alias を何に書き換えるか」の具体ルールは本書時点で未確定（FR-7.8）。ユースケースを testdata として積み上げ、安全な変換規則を `docs/fix-cases.md` に明文化しながら確定させる（DEC-3.1）。
- 型情報を使った参照書き換えは既存 `shape.PkgNameOf`/`shape.SelectorIdentsOf` を再利用する。
- `astutil.AddNamedImport(fset, file, alias, path)` の無 alias（`""`）挙動は要確認（`docs/draft.md` にも未検証と記載）。
- 衝突判定は既存 `shape.NameVisibleAt` を利用。DEC-11.22（精密化）は本 issue では踏み込まず、現行の保守的近似のまま。
