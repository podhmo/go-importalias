# ADR-01: 実装 issue のライフサイクル（docs/issues/ と closed/）

- **日付**: 2026-07-21
- **ステータス**: 採用
- **対象**: `docs/01decision.md`（確定済み実装決定）の DEC-10.1 実装着手順を、実際のコード実装として遂行していくフェーズの進め方。

## 番号系列に関する注記（混同防止）

- `docs/00origin.md` 内の **ADR-1〜ADR-6** は、機能仕様書の中で「検討され却下・変更された提案」を記録したもの（仕様内の決定記録）。
- 本 `docs/adr/` ディレクトリの ADR（**00**, **01**, …）は、**プロジェクトの進め方そのもの（運用 ADR）** を記録する別系列である。
  - ADR-00: `draft.md` / `02notice.md` / `01decision(.pre).md` ループ（設計原則の確定手順）。
  - ADR-01: 本書（確定済み DEC の実装遂行手順）。

## 背景・課題

ADR-00 のループにより、設計原則・パッケージレイヤ構成レベルの未決事項は `docs/01decision.md` の DEC-11.1〜11.22 としてほぼ確定した。現状のコードは walking skeleton（scan/fix のテストハーネスが動き、FR-6.10 の検出＋rename fix のみ実機能）であり、ここから先は DEC-7.5 が述べる「テストケースを追加してから実装する」ループの繰り返しで機能を積み上げていく段階に入る。

この実装遂行フェーズでは、ADR-00 の「PRE → 確認 → DEC」ループ（＝まだ決まっていない設計原則を確定する作業）とは目的が異なり、「**すでに確定した DEC を、どの順序で、どのファイルに、どういう終了条件で落とすか**」を管理する仕組みが必要になる。

## 決定

### 1. 実装単位を `docs/issues/` に起票する

- DEC-10.1 の残作業を、独立に着手・テストできる単位の issue として `docs/issues/NN-<slug>.md` に起票する。
- 各 issue は以下の統一フォーマットを持つ:
  - **目的**: この issue で何が動くようになるか（1〜2文）。
  - **対象 DEC・FR**: 根拠となる `docs/01decision.md` の DEC 番号・`docs/00origin.md` の FR 番号。
  - **変更ファイル**: 新規/変更するファイルのパス。
  - **実装メモ**: 実装上の勘所（既存ハーネス・既存関数の再利用箇所など）。
  - **終了条件**: 満たすべきテスト・振る舞いを検証可能な形で列挙する。
  - **依存**: 先に closed であるべき issue。

### 2. open / closed のライフサイクル

- `docs/issues/` 直下 = **open**（着手可能・進行中）。
- issue の**終了条件をすべて満たしたら**、そのファイルを `docs/issues/closed/` へ移動する = **closed**。
  - 移動のみで内容は残す（実装履歴として参照できるようにする）。closed 側に「完了日・対応コミット」等を追記してよい。
- 索引 `docs/issues/README.md` は **open のみ**を一覧する。closed は `closed/` 側で履歴として残す。

### 3. ADR-00 ループとの往復

- 実装の途中で、既存 DEC では答えの出ない**設計原則レベルの新たな未決事項**が出た場合は、issue の中で抱え込まず ADR-00 のループ（`docs/01decision.pre.md` に PRE として起票 → ユーザー確認 → `docs/01decision.md` に DEC 追記）へ戻す。
- 逆に、`docs/02notice.md` は引き続き「実装しながらの気づき」の蓄積ログとして使う（本 issue ループと併存）。

## 判断基準: 何を issue にするか

- **issue にする**: 確定済み DEC/FR を実コードへ落とす、独立して着手・テスト可能な作業単位。
- **issue にしない**: まだ設計原則が未確定の論点（→ ADR-00 ループへ）。テストハーネスの機械的な構成の詳細のように「実装しながら決める」とすでに DEC-7.5 で方針化されている事項（→ 実装の中で都度判断）。

## 結果

DEC-10.1 の残タスクを 13 件の issue（01〜13）＋索引として `docs/issues/` に展開した。着手順・依存関係は `docs/issues/README.md` を参照。
